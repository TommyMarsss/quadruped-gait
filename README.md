# 四足机器人步态生成与静态稳定性检测

纯 Go 标准库实现的四足步态仿真：给定期望速度曲线与步态类型，生成各足端
摆动/支撑相轨迹，处理步态间的安全切换，并对每一帧做静态稳定性判据评估。
仿真结果导出为**单一静态 HTML 文件**（数据与逻辑全部内嵌，原生
HTML/CSS/JavaScript，零第三方依赖），浏览器打开即可从俯视图与侧视图回放。

## 运行

```bash
go run .        # 仿真并生成 replay.html，同时打印步态参数预检报告
go test ./...   # 自动化测试
open replay.html
```

回放页面：空格或按钮播放/暂停，滑块与速度选择，底部时间轴（绿=稳定、
红=裕度不足、黄线=步态切换点）可点击定位；裕度不足的帧会以红色高亮
两个视图并显示警告条。

## 步态相位模型

每条腿由归一化相位驱动：

```
φ_i(t) = frac(f · t + o_i)        f: 步态频率(Hz)，o_i: 该腿相位偏移
φ_i ∈ [0, β)   → 支撑相（足端在世界系固定，机体相对其运动）
φ_i ∈ [β, 1)   → 摆动相（足端沿摆线从抬腿点运动到规划落点）
```

内置两种步态（`gait.go`）：

| 步态 | β | 相位偏移 (FL, FR, RL, RR) | 特点 |
|------|-----|---------------------------|------|
| walk（爬行/横向顺序步态） | 0.75 | 0.5, 0.0, 0.75, 0.25 | 抬腿顺序 RL→FL→RR→FR，任意时刻 ≥3 足支撑，可静态稳定 |
| trot（对角小跑） | 0.55 | 0.0, 0.5, 0.5, 0.0 | 对角腿对 (FL,RR)/(FR,RL) 同步，最少 2 足支撑，动态步态 |

支撑相中足端在世界系保持不动（测试断言滑移恒为 0）；摆动相落点按
Raibert 式中性落点规划：

```
p_td = p_body(t_td) + p_nominal + v · T_stance / 2
```

横向落点取摆动中心线（y=0）而非机体瞬时横向位置——横向重心摆动是机体
的周期运动，若足端跟随它放置，支撑多边形会被不同相位落地的足端拉歪，
反而吃掉稳定裕度（调试中实测确认）。

## 摆线（cycloid）摆动轨迹的选择依据

```
水平: p(s) = p0 + (p1 − p0)·(s − sin(2πs)/2π)
竖直: z(s) = h·(1 − cos(2πs))/2,  s ∈ [0,1]
```

- 两个分量在 s=0 与 s=1 处一阶导数**严格为零**：抬腿与落地瞬间足端速度
  （含垂直方向）连续收敛到 0，不存在硬性速度跳变（落地冲击小）；
- 竖直速度解析式 `dz/dt = h·π·sin(2πs)/T_swing`，测试断言端点处 |v| < 1e-12；
- 相比五次多项式轨迹无需解算系数，单次求值 O(1)，且形状对称、峰值高度
  恰为 h（s=0.5）。

## 步态切换规则（等待当前相完成）

`Sim.RequestSwitch` 只登记待切换步态，不立即生效。每个时间步按以下顺序
结算（`sim.go` 的 `Step`）：

1. 先结算**触地事件**（摆动相 → 支撑相）；
2. 若存在待切换步态、且本步发生了触地、且**四足当前均处于支撑相**，
   此刻才替换相位表（相位原点重置为当前时刻）；
3. 再按（可能已更新的）相位表结算抬腿事件。

由于切换只发生在所有摆动腿完成摆动相、四足落地的安全时刻，任何足的
轨迹都不会中断或瞬间传送：刚触地的足保持落点，其余足保持支撑位置，
新相位表要求摆动的腿从当前位置起摆。测试
`TestGaitSwitchWaitsForSwingCompletion` 验证：t=3.13s（RL 摆动中途）
请求切换，切换必须延迟到 t=3.25s 该腿触地后才发生，且切换帧四足
z≈0、足端位置跳变 < 1cm。

## 静态稳定性判据

采用经典的**支撑多边形（support polygon）判据**（McGhee & Frank,
"On the Stability Properties of Quadruped Creeping Gaits", 1968）：

- 取当前支撑足足端在水平面的投影，求凸包（Andrew 单调链）；
- 静态稳定 ⟺ 支撑足 ≥ 3 且重心投影落在凸包内；
- **稳定裕度** = 重心投影到凸包各边的最小有符号距离（内正外负），
  裕度 ≥ 阈值（默认 0.02 m）才判为稳定帧。

两个层面的检测：

1. **参数预检**（`AnalyzeGait`）：不跑仿真，直接采样一个相位周期统计
   最少同时支撑足数（<3 即静态不可行，如 β 过小/摆动相占比过大），并
   检查步幅 `v/f` 是否超出腿部工作空间（步频相对速度过低）。几何上
   必然倾覆的参数组合在生成轨迹前就被明确报告；
2. **逐帧检测**：仿真每帧计算裕度，回放页面高亮裕度不足的帧。

walk 段叠加了横向重心摆动（lateral sway）：β=0.75 时三足支撑三角形的
对角边穿过机体中心附近，必须把重心投影摆向支撑侧才有正裕度。重心
轨迹为 `y = −A·tanh(k·sin(2πf·t))`——符号需求是半周期方波（{RL,FL}
摆动时在负侧，{RR,FR} 摆动时在正侧），用 tanh 整形实现快速过零。
注意 β=0.75 的 walk 不存在四足同时支撑区间，换腿瞬间裕度必然过零，
因此 walk 段仍有少量（约 7%）换腿瞬间的低裕度帧，属物理本质而非缺陷。

## 场景（`main.go`）

静止（1s）→ walk 加速到 0.2 m/s → t=4s 请求切换 trot（实际于 t≈4.25s
安全点切换）→ 加速到 0.35 m/s 小跑。输出包括：四种步态参数组合的预检
报告（含两个故意构造的不稳定组合）、切换事件、分段稳定性统计、
连续性自检，以及 `replay.html`。

## 局限

- 静态判据对 trot 等动态步态必然报不稳定（双足支撑区间），报告中已
  明确标注"仅可作为动态步态使用"，动态稳定性（ZMP/捕获点等）不在
  本判据范围内；
- 机体假设为质点+刚体平动，无姿态（roll/pitch）动力学；
- 落点规划假设摆动期内速度近似恒定。
