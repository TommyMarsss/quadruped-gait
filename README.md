# 四足机器人步态生成与静态稳定性检测（Go 标准库）

给定期望速度与步态类型，计算四足各腿在一个周期内的摆动相 / 支撑相时序与
足端摆线轨迹，处理步态切换时的相位连续性，并逐帧检测静态稳定性；
最后把全部结果输出为**单一离线 HTML 文件**（数据与逻辑内嵌、无服务、无第三方依赖）。

* 后端：仅使用 Go 标准库（`math`、`sort`、`encoding/json`、`fmt`）。
* 前端：单个 `report.html`，原生 HTML/CSS/JavaScript + Canvas，无任何框架或图形库。

## 构建与运行

```bash
go run ./cmd/report -o report.html
# 可选参数
#   -walkv 0.15 -trotv 0.45 -walkf 0.8 -trotf 2.0 -switchat 6.0
open report.html        # macOS；其它系统用浏览器直接打开该文件即可
```

用浏览器打开后可**同时**看到俯视（X–Y）与侧视（X–Z）回放、支撑多边形、
重心投影与稳定性结论；稳定帧绿色、**稳定性裕度不足的帧红色高亮**，
时间轴上红色区段即不稳定区间、黄色竖线为步态切换点。

页面支持：空格播放/暂停、←/→ 逐帧、`‹ 不稳定 / 不稳定 ›` 在不稳定帧之间跳转、
播放倍速，以及 URL 参数 `?t=9.2`（跳到第 9.2 秒）或 `?frame=420`（直达某帧）。

## 1. 步态相位模型

步态由周期 `T=1/f`、占空比 `β`（单腿在一个周期内处于支撑相的比例）
和各腿摆动相起始的归一化相位偏移 `φ_i` 完全描述。第 `i` 条腿在周期相位
`p∈[0,1)` 下处于摆动相当且仅当

```
wrap(p − φ_i) ∈ [0, 1−β)
```

摆动相时长 `t_swing = (1−β)T`，支撑相时长 `t_stance = βT`。

实现了两种步态：

* **爬行 walk（四拍波爬行步态）**，偏移序 `FL → BR → FR → BL`：

  ```
  φ_FL=0,  φ_BR=1/4,  φ_FR=1/2,  φ_BL=3/4
  ```

  这是 McGhee (1968) 给出的使纵向稳定性最大的四拍顺序。默认工程占空比
  `StableWalkDuty=0.85`（理论最小占空比 `WalkDuty=0.75` 见下节）。
* **对角小跑 trot**，对角足成对、相差半周期：

  ```
  φ_FL=φ_BR=0,  φ_FR=φ_BL=1/2,   β=0.5
  ```

  任意时刻恰有一对对角足支撑，属于**动态**步态（靠角动量/主动平衡稳定，
  不在静态判据覆盖范围内），程序会把这些帧明确标注为“静态不适用”，
  而不是静默当作稳定。

### 步长与无滑动约束

支撑相内足端相对地面静止，因此相对髋关节匀速回退。摆动步长取

```
L = v_td · βT
```

落地点设在“落脚时刻髋关节位置”前方 `L/2`，使足端在支撑相内相对髋关节
从 `+L/2` 对称回退到 `−L/2`，保证摆动终点与支撑轨迹位置连续、无打滑突变。

## 2. 摆线轨迹与落脚速度收敛

摆动进度 `u∈[0,1]`（0=抬脚，1=落脚）的**水平方向**采用修正摆线规律：

```
s(u)  = u − sin(2πu)/(2π)
s'(u) = 1 − cos(2πu)
s''(u)= 2π sin(2πu)
```

抬脚高度方向采用摆线拱：

```
h(u) = (1 − cos(2πu))/2,        峰值 h(1/2)=1
z(u)  = H · h(u)
```

实际位置/速度由链式法则 `d/dt = (1/t_swing)d/du` 得到（见
`trajectory.go` 的 `SwingFoot`）。

**选择依据**：摆线（cycloid）类规律同时满足

```
s(0)=0, s(1)=1,
s'(0)=s'(1)=0,  s''(0)=s''(1)=0,
h(0)=h(1)=0,    h'(0)=h'(1)=0
```

即足端在抬脚与落脚两端的**位置、速度、加速度都与支撑相连续衔接**。
落脚瞬间 `vz = H·π·sin(2π)/t_swing = 0`，是平滑收敛而非硬性速度跳变——
这正是题目“摆动相末端落地时垂直速度必须收敛到可接受范围”的要求。
相比之下，线性插值/常速摆腿在落脚处速度非零，会产生冲击。
代码同时记录每次落脚前一瞬（`u=1−1e-12`）的速度与落脚位置偏差，
实测垂直速度残差在 `1e-11 m/s` 量级、位置跳变在 `1e-18 m` 量级。

## 3. 步态切换的连续性处理

切换**不是**在请求时刻立即替换相位表。`RequestSwitch(t_req, …)` 只是登记请求，
生成器遵循如下事件驱动协议（见 `generator.go`）：

1. 请求时刻未到（可提前登记）时，一切调度照常，不干扰任何在摆腿；
2. 请求到点后，**抑制所有新的抬脚**。此刻正在摆动的腿允许其
   **完整走完当前摆动直到落脚**（`endSwing`），绝不中途打断；
3. 到达支撑相边界的腿则延展支撑、不抬起；
4. 一旦“至少一条腿完成了当前相”且“四足全部着地”，进入**四足驻留**过渡：
   速度按减速度线性回零、保持短暂驻留；
5. 驻留结束、四脚着地时才真正替换相位表，并从新步态相位 0 的锚点
   连续起步。

因此切换瞬间：旧步态下没有任何脚处在摆动途中，没有脚被瞬间传送到
错误位置（实测各足位置跳变上界为 0）；切换只发生在一个明确的离散事件点。
请求时刻与实际切换时刻都会记录（`SwitchEvent.RequestT / SwitchT`）。

## 4. 静态稳定性判据

采用 **McGhee & Frank (1968) 的静态稳定裕度（Static Stability Margin）**：

1. 取所有着地足在水平面的位置，用 Andrew 单调链算法求**凸包**得到支撑多边形；
2. 计算机身重心水平投影到多边形**每条边所在直线的有符号距离**
   （凸包逆时针，点在边内侧时为正）：

   ```
   d_i = cross(e_i, c − a_i) / |e_i|
   ```
3. `S = min_i d_i` 即静态稳定裕度：
   * `S ≤ 0`：重心投影在多边形外（或在边界上），静态倾覆；
   * `0 < S < S_min`：几何上在内但裕度不足；
   * `S ≥ S_min`（默认 `MarginThreshold = 0.02 m`）：静态稳定。

支撑足少于 3 只（点/线段无法约束平面倾覆）或凸包退化（共线）时
直接判不稳定，并给出原因。

### 参数层的前置拦截（不生成几何上必然倾覆的步态）

`CheckFeasibility` 在生成轨迹前扫描一个周期内的相位事件区间，
求出**任意时刻最少同时支撑脚数** `n_min`：

* `n_min < 3`：该（频率, 占空比）组合无法保持静态稳定。对四拍爬行，
  `β=0.75` 是理论极限——此时相邻三足支撑三角形只共享一条边，
  重心在换脚瞬间恰落在边上（零裕度）；**β 略低于 0.75 立即出现两足
  同时摆动的瞬间，几何上必然倾覆**，必须被明确拒绝。
* 默认 `β=0.85` 提供非零的四足支撑重叠窗口 `(β−0.75)T`，
  重心可在该窗口内连续横向预置到下一只摆动脚的对侧，再抬脚。
* 频率不改变相位几何，但步频过高会使摆动相内来不及完成质心调整，
  因此另设准静态频率上限 `MaxStaticFrequency=1.5 Hz`。

这些不稳定组合都会返回明确的 `Reason`，而不会产出一个自己却不知情的倾覆步态。

### 质心预置模型

仿真中质心纵向位于机身中点（落在所有三足支撑三角形的纵向交集内），
横向在每次四足支撑窗口内线性转移到“下一只摆动脚对侧 `b/3`”的预置点，
抬脚前到位、摆动相内锁定。这与真实静态爬行“先移重心、再迈腿”的时序一致，
使 walk 段逐帧静态稳定（实测最小裕度约 0.035 m）。
